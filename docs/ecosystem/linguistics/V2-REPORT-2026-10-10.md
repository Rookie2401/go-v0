## 1. What was already available

- Six analysers (`src/adapters/{sq,es,de,hi,th}.ts`, `norwegian/`) with word lists of 1,350–3,860 lexemes, rule-based form
  analysis, constructions, phrases, production checks; Hindi verb groups; German/Norwegian compounds; Thai tokenizer.
- Schema-3 dictionaries built from kaikki.org (Wiktionary) for sq/es/de/hi/th (91k / 808k / 358k / 39k / 20k entries),
  hosted at `https://rookie2401.github.io/go-v0/dict/<lang>/`; raw kaikki dumps on disk; no Norwegian dictionary.
- A card with lemma, meaning, grammar, form, confidence, phrases, a learner-model row; GoLearn Active (page scan, underlines,
  self-rating); the Repository Layer A (`repository-linguistics`) with analysis-level statuses; GoReview intake.
- Prior measurements: Albanian on UD treebanks (57.7 % first-reading POS), Norwegian blind holdout, Spanish on dictionary
  examples, Thai segmentation F1; Hindi nothing accepted. See COVERAGE-AUDIT.md §3.

## 2. Why definitions and grammatical data were missing

Measured in Stage 1 (COVERAGE-AUDIT.md §2, baseline-2026-10-10.json): the data was on disk but not delivered.
(a) The worker had no dictionary location without an account, and `assetBaseUrl "./"` pointed at the extension folder, which
carries Albanian only; (b) the card asked the dictionary only for seed-list lemmas; (c) failures were silent; (d) form-only
entries (inflected forms) were not followed to their headword; (e) the schema-3 build dropped the inflection tables,
etymology, IPA, audio and relations that kaikki carries; (f) no adapter generated paradigms; (g) no adapter produced syntax
beyond a few role labels (sq 19.5 %, th 35 %, others 0–8 %).

## 5. Do full paradigms genuinely work?

Yes for the listed kinds, with the honest caveats above: on the card the All forms section shows a layout table with the
selected cell marked, each cell's status (✓ both agree, ◌ dictionary only, ~ rules only, ‼ conflict with both forms shown),
notes and sources. Verified in the pane for `librin` → 16 cells, all ✓ (BROWSER-VERIFICATION.md). Availability on the probe
corpus: sq 96 %, es 79 %, de 88.5 %, hi 83.5 %, th 95 % (constructions). Dictionary rows are aligned to the generated keys
by `alignTable` (constant Gender, union cases, headline rows dropped) — without it the two halves did not meet.

## 7. Etymological sources operational

Wiktionary via kaikki.org only (CC BY-SA 4.0): the etymology text, the template chain (inherited / borrowed / derived /
cognate …) with ~200 language codes named, cognates, and the affix/compound templates for word structure; plus the analysers'
own compound/clitic/causative parts and a generated stem/ending (marked provisional). Never generated: no record → "No
documented origin". Availability: etymology 92–98.5 %, word structure 10–40 % (templates 0.5–10 %), cognates 26–85 %
(ETYMOLOGY.md). Norwegian: none (no dictionary).

387 KB, worker 537 KB (ceiling raised to 560 KiB), other analysers remain separate chunks.

## 12. Remaining gaps

LIMITATIONS.md has the full list. The important ones: AI-judged gold only; engine bugs found by the cross-checks left
unfixed (adapter versions pinned); Albanian syntax at UAS 53 % on real treebank text; Thai segmentation and unknown words;
Norwegian without any dictionary; word structure mostly a stem/ending heuristic; the Repository resolver does not yet run
`syntax()`/`paradigm()` itself (states stay `unknown` unless the caller passes evidence); GoReview's validation queue is not
rendered; a table row shared by several persons verifies only its first cell on the card.

## 13. Licensing and hosting concerns

- All dictionary content is Wiktionary via kaikki.org, CC BY-SA 4.0; attribution is shown on the card and recorded in every
  shard manifest; recordings are Wikimedia Commons files, listed by name with their licence context, not played.
- The owner's course texts and verified Scripture slices were used for measurement only; nothing was sent to an external
  service; nothing was downloaded; no blocked integration was enabled.
- Hosting decision needed: the `full/` shards for German (409 MB) and Spanish (244 MB) are too large to publish on GitHub
  Pages as they are, and `npm run build` copies `public/` into `dist/`. Options: publish sq/th/hi `full/` only (126 MB) and
  keep de/es Level 2 for a configured service; or shrink the shards with a tag-set table (forms are ~70 % of the bytes; gzip
  already gives ~10×).
