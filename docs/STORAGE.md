# Go — Storage model, backup and restore

## 1. Where data lives

Everything is local to the device. There is no server and no account.

| Place | What | Notes |
| --- | --- | --- |
| IndexedDB database `go-v0` (Dexie 4, `src/db/dexie.ts`) | One object store per `AppStore` table (see §2), plus `blobs` for audio bytes | The schema string for each table is `id` plus the fields listed in `INDEXES` (`src/core/store.ts`). Schema version 1. |
| `blobs` object store (same database) | Audio bytes, content-addressed (`sha256:<hex>`, or `fnv:<hash>` without WebCrypto) | Holds both generated audio (rebuildable) and the learner's own recordings (irreplaceable). Rows reference blobs by id; bytes are never a column on a record. |
| `localStorage` | Per-device conveniences only (below) | Every access is guarded; the app works with it blocked. Never holds learning data. |
| Memory | `createMemoryStore()` | Tests and scripts only. |

`localStorage` keys (all written by `src/ui/prefs.ts`):

| Key | Contents |
| --- | --- |
| `go-v0:prefs` | JSON of reading preferences: highlight, default playback speed, transcript mode, font size, theme |
| `go-v0:active-user` | Id of the learner last used on this device |
| `go-v0:chosen-course` | Team (course) chosen at onboarding / Settings; bootstrap creates the learner only after this exists |

These three are not in a backup. After restoring on a new device, choose the team once (or let the restored learner row set the course) and adjust preferences again.

## 2. Tables: source of truth vs derived

**Source of truth** = cannot be recomputed; lose it and it is gone. **Derived** = rebuildable. **Corpus** = re-imported from `data/corpus` by the app.

| Table | Class | Backed up? | Notes |
| --- | --- | --- | --- |
| `users` | source | yes (the learner's row) | One per learner on the device. |
| `events` | **source** (append-only log) | yes, all of the learner's events | The only write path to learner state. `dedupeKey` makes re-delivery harmless. |
| `testimonies` | source | yes | The learner's testimony per language; `currentRevisionId` pointer. |
| `revisions` | source (immutable) | yes | Every accepted state of the testimony; never overwritten. |
| `suggestions` | source | yes | GoTell suggestions and what happened to them. |
| `drafts` | source | yes | Autosaved working draft (one per learner + language), monotonic `seq`. |
| `recordings` | source (metadata) | yes (metadata always; audio optional) | The learner's shadowing recordings. |
| `blobs` (audio assets) referenced by `recordings.assetId` | source (bytes) | only with "include recordings" | Base64 inside the backup, byte-exact. |
| `meta` | mixed | learner-scoped non-policy rows only | See "meta" below. |
| `texts` of `kind: 'testimony'` and their `sections`, `paragraphs`, `sentences`, `tokens`, `analyses`, `rescues`, `phraseOccurrences`, `patternOccurrences` | source (private, per revision) | yes | Created by `GoTell.acceptRevision` (ADR 9). Reachable only from the learner's own revisions. Analyses are kept as they were, not re-run. |
| `corpora`, `sources`, `lemmas`, `phrases`, `patterns` rows that the testimony content points at | reference | yes, added-if-absent on restore | So the restored text is not dangling on a device whose corpus has not been imported yet. Existing rows are never modified. |
| `encounters` | derived | **no** | Folded from `events` by GoLearn. |
| `learnerItems` | derived | **no** | Folded from `events` by GoLearn. |
| `texts` (story, dialogue, nonfiction, scripture, transcript, generated-prep) and their sections/paragraphs/sentences/tokens/analyses/rescues/phrase and pattern occurrences | corpus | no | Re-ingested from `data/corpus`. |
| `languages`, `courses` | config | no | Seeded from `src/core/config.ts`. |
| `lemmas`, `phrases`, `patterns` (corpus-wide) | corpus | no (only the ones the testimony references) | Produced by ingestion. |
| `voices`, `audioAssets`, `audioSegments`, `alignments`, `manifests`, `audioJobs`, `pronunciations` | derived (GoListen) | no | Regenerated by `ensureAudio` / the job runner. Generated audio is never part of a backup. |

`meta`: GoLearn stores its evidence-policy version per learner in `meta` so that a mismatch triggers a rebuild. That row says "derived state is current", which is exactly what a restore invalidates, so policy/derived markers (any id containing `polic`) are **not** exported as data. The policy version seen at export time is recorded in the file header as `policyVersion` for information, and restore deletes that learner's policy marker when it adds events (or in replace mode), so `GoLearn.ensureCurrent` will rebuild. Other meta rows whose id contains the learner id as a `:`, `|` or `/` separated segment travel with the backup and merge by newer `updatedAt`.

## 3. The backup file

`exportLearner(store, userId, { includeRecordings? })` → JSON, `format: "go-backup"`, `version: 1`:

```
{ format, version, createdAt, userId, policyVersion?, includesRecordings, counts, checksum,
  data: { user, events, testimonies, revisions, suggestions, drafts, recordings,
          testimonyContent: { texts, sections, paragraphs, sentences, tokens, analyses, rescues, phraseOccurrences, patternOccurrences },
          reference: { corpora, sources, lemmas, phrases, patterns },
          meta, assets: { [assetId]: { mime, base64, bytes } } } }
```

- **Contains**: exactly the source-of-truth rows in §2 for **one** learner. Rows are found by `userId`, or by being reachable from that learner's own revisions. Another learner's rows cannot be included, and a file that contains any is rejected on restore.
- **Omits**: corpus texts, generated audio and all GoListen state, encounters, learner items, languages/courses, other learners, `localStorage` preferences, and (unless asked) recording audio.
- **Checksum**: `fnv1a64:<hex>` over the canonical (sorted-key) JSON of `data`, using `hash` from `src/core`. It detects truncation, edits and corruption; it is not a signature and does not stop a determined person from forging a file.
- Recording **metadata** is always present. With `includeRecordings` the audio is embedded as base64 (about 4/3 of its size). Without it, restore brings the recording rows back and reports `metadataWithoutAudio`.

## 4. Restore

`restoreLearner(store, file, { mode: 'merge' | 'replace' })` accepts the parsed object or the raw JSON text. It validates first (`validateBackup`) and throws `BackupError` (`.issues`, each with `code`, `severity`, actionable `message`, `path`) before writing anything if the file is not JSON, is not a Go backup, has another `version`, fails its checksum, is incomplete, carries corpus text or another learner's rows.

- **merge** (default): additive, never deletes. Events skip by id, then by `dedupeKey`; an id that already belongs to another learner is skipped and reported. Rows go in by id. A draft only replaces the local one if its `seq` is higher (equal `seq`: newer `updatedAt`), so a stale backup never overwrites newer typing. Revisions, testimony texts and recordings are immutable: the device's copy wins on any difference. The testimony pointer moves only to a revision with a higher number. Suggestions only move forward (`shown` → `rejected` → `edited` → `accepted`). Meta takes the newer `updatedAt`. The learner row is kept if it already exists.
- **replace**: first removes **that learner's** existing events, testimonies, revisions, suggestions, drafts, recordings, private testimony texts, meta and stale derived rows (encounters, learner items), then restores the file. Other learners are never touched. Audio blobs are content-addressed and shared, so they are left in place.
- **Idempotent**: restoring the same file twice changes nothing (`changed: false`, `needsRebuild: false`).
- `RestoreReport`: `needsRebuild` (true when events were added or replaced: call `GoLearn.rebuild(userId)` / `ensureCurrent`), `changed`, per-table `{ added, updated, unchanged, keptExisting }`, `events` counts, `removed`, `recordings`, `warnings`.

The restore runs in one `store.transaction` (a real Dexie read-write transaction). Audio bytes are written before it because hashing is asynchronous and lives in a different object store; if the transaction then fails, at worst some content-addressed audio is left unreferenced.

## 5. Privacy

Testimony text, its personal audio and the learner's recordings never leave the device unless the learner explicitly exports a backup. There is no upload, sync or telemetry. The backup file is plain JSON (recording audio as base64): it is not encrypted, so the learner should treat it like the private document it is (keep it off shared drives). Another learner profile on the same device cannot read it: `GoTell.forUser` enforces ownership in the app, and export/restore only ever read or write the requested learner's rows.

## 6. Moving to a new device

1. Old device: Settings → Export backup (tick "include my recordings" to keep the audio). Save the `.json`.
2. New device: open the app, choose the same team so the course and corpus load (corpus texts come with the app, not the backup).
3. Settings → Restore backup, choose the file, mode **Merge** (or **Replace** to make the device match the file exactly). Read the warnings.
4. If the report says `needsRebuild`, the app rebuilds derived state from the restored events. Nothing else needs doing; personal testimony audio is regenerated on demand.
5. Re-set preferences (they live in `localStorage` on the old device).

## 7. How derived state is rebuilt

- **GoLearn** (`encounters`, `learnerItems`): `rebuild(userId)` replays that learner's event log under the current evidence policy. `ensureCurrent` does it automatically when the stored policy version differs from `GoLearn.policyVersion`; restore clears the marker so this happens on the next start. Exposure, help and demonstration are all in the events, so the rebuilt state equals the original.
- **GoListen** (voices, segments, assets, manifests, alignments): `ensureAudio(textId)` regenerates audio for any text on demand, including the private testimony texts. Cache keys include `contentVersion`, so nothing stale is reused.
- **Corpus** (texts, lemmas, phrases, patterns): re-ingested from `data/corpus` by the app on first start.
- The one thing that can never be regenerated is the learner's own words and voice, which is why the backup exists.
