# GoLearn word library

GoReview ranks eligible encountered words comparatively using the existing candidate scores, with saved-word preference and deterministic ties. The highest words remain highest even when all raw scores are small. The screen says **Low comparative priority** for words farther down that list. Encountered Seen words may receive recognition practice; this does not assert comprehension. New/Automatic gates, invalid analyses, missing answer keys, unavailable listening, explicit Later, and dismissed or suspended cards remain protected.

Opening GoReview automatically adds the highest-ranked buildable cards through normal CardAdded events, bounded by the new-item preference per admission batch. Repeated successful loads of unchanged evidence and preferences do not fill the deck with lower-ranked leftovers. Failed builds and unavailable resources are retried, and preference or evidence changes trigger reconsideration. Existing cards and FSRS history are preserved. Each card has a stable automatic identity; concurrent tabs deduplicate the same card, though the per-batch admission limit is not a cross-device transaction. Candidate retrieval pages through the complete Repository ranking instead of stopping at the first 200.

When GoLearn Active is enabled on a permitted reader, individual words that remain visibly displayed for 800 ms are recorded as exposure. Scanning ahead does not record off-screen words. Hidden tabs, stopped Active mode, and words without visible layout are excluded. The toolbar reports acknowledged distinct word forms, separately from scanned words. Reading exposure does not establish comprehension or mastery. Previously unrecorded reading cannot be reconstructed from a practice deck.

Hindi's Repository resolver uses the real experimental Hindi analyser instead of a generic Latin-only fallback. To support Hindi without a server, the background worker now includes that analyser; its build is approximately 988 KB, versus roughly 500 KB previously. The bounded worker budget is 1050 KB. Content scripts still load Hindi separately, and network, permission and fixture-isolation checks remain enforced.

GoLearn keeps recorded encounters and learner marks in the existing Repository. Account storage uses SQLite, keyed by learner and unit; the extension keeps its device repository in browser local storage and synchronizes when signed in. No second vocabulary database or migration of existing history is needed.

Open **My words** from GoLearn's home screen. The vocabulary screen supports search, language-specific knowledge filters, encounter dates, assistance, source and review status. Knowledge order is the default: New, Seen, Recognized, Familiar, Known, Automatic. Within a level, lower retention and greater uncertainty come first. Existing manual marks and the evidence-based knowledge engine retain their meaning. Recent and alphabetical ordering are also available.

The screen reloads the first page when it regains focus and offers Refresh words. A learner's progress can move records in the list; refresh before continuing pagination after progress changes. Ordering is a view of current knowledge, not a replacement for the GoReview spaced-repetition schedule.

Explicitly sorted API requests read the learner's complete filtered vocabulary before returning a page, so ordering is global rather than limited to the first store page. Omitted sort retains the older unit-ID cursor behavior. Sorted pagination uses the last unit as its boundary. Concurrent learning updates can change boundaries; refresh starts a new view. This implementation scans the learner's vocabulary for each sorted request; very large libraries will need indexed ordering or versioned snapshots for lower latency.

Failed event persistence is reported rather than acknowledged as durable. Pending writes are retried while the repository remains open. Storage must recover before closing the browser to preserve pending data. Tests cover quota recovery and deletion during pending writes; no storage system can promise persistence while the underlying device refuses writes.

Validation distinguishes automated repository/UI tests and production builds from a live browser session. Reload the unpacked extension to load rebuilt files. A separately running account service must be restarted to load changed server code.
