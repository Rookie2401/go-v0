# Morphology coverage audit

Status: source inspection, 2026-10-30. This is an inventory of what code and pack manifests say exists, not a correctness certification. The working tree was clean before this audit. No `AGENTS.md` was found in the repository. Existing project docs consistently state that linguistic content is machine-drafted and not human-reviewed; see `docs/ecosystem/linguistics/LIMITATIONS.md`.

## What readers can install

`packages/language-packs/src/registry.ts` registers `sq`, `es`, `de`, `hi`, `th`, `la`, `he`, and `el` (plus Norwegian). `installablePacks()` filters those manifests by status. `packages/language-packs/src/packs/experimental.ts` says installable means experimental, explicitly not production-ready; validation cases are short machine-authored checks, not a representative language evaluation. The browser parser has entries for all eight (`packages/golearn-extension/src/parser/registry.ts`); non-Albanian analyzers are loaded on demand (`src/analysers/loaders.ts`). Hebrew and Greek additionally have full index assets loaded by `packages/golearn-extension/src/lexicon/prepare.ts`; a failed set leaves analysis running with the available core and an unavailable-set indication.

The detailed paradigm notes are in `docs/ecosystem/linguistics/PARADIGMS-{sq,es,de,hi,th}.md`; these languages have generated-rule/dictionary-table comparisons. Greek, Hebrew and Latin implement their own distinct paradigms, but the repository has no equivalent checked corpus-wide morphology score here. Presence of a `paradigm()` method should not be read as proof that each generated cell is correct or that a paradigm is available for every lemma.

End-to-end analyzer-to-translation regression coverage remains incomplete across these languages. The new projection-level tests only establish null-preserving lane separation and verbatim pass-through of explicit feature fixtures; they do not evaluate analyzer output or translation accuracy.

## Safe interpretation and fallback

Use the adapter's actual evidence state: preserve all competing readings; keep unions where endings are ambiguous; label rule-only forms provisional/guessed; report “no reading” when the analyzer has none; and for Thai state that the language does not inflect while showing only supported constructions/segmentation. Dictionary tables are corroborating source material, not ground truth (especially Albanian and Hindi); a rule/dictionary disagreement should remain conflicted. A missing Greek/Hebrew index means core-only analysis, not full coverage. Do not convert capability flags, validation examples, dictionary entry counts, or in-corpus availability into accuracy claims. For stronger claims, require independently reviewed contextual gold data and language-specialist review; meanwhile show source/provenance and uncertainty on the card.

## Biblia reader and lookup path (lexical-boundary notes)

Biblia is a separate reader package but shares GoLearn's card and parser: `packages/biblia/src/app.ts` imports `parseSelection` and `createCardUI`, passes `he-bib`/`arc-bib` or `el-koi` as the text period, and attaches the source's own Open Scriptures/MorphGNT reading as a `gold` hint. In `src/parser/index.ts`, this hint only moves a candidate already present in the adapter's analyses to the top; it does not create a reading. `packages/biblia/src/levels.ts` uses those same parser item IDs. `packages/biblia/src/data.ts` loads the Biblical Hebrew and Koine indexes and reports when it must fall back to core. Thus the Bible edition's lexical/morphological annotation is not directly substituted for the GoLearn adapter; it is a candidate-ordering hint, gated by an existing matching candidate.

Useful inspection pointers for any follow-on popup/lexical-boundary review:

- `packages/biblia/src/app.ts:292-360` maps printed scripture words to word buttons, supplies period and source annotation, and calls GoLearn parsing on lookup.
- `packages/biblia/src/data.ts:72-80` installs the full OSHB and Koine indexes; `packages/biblia/src/app.ts:455-474` prepares Ancient Greek and Modern Hebrew variant shards per chapter.
- `packages/golearn-extension/src/parser/index.ts:35-64` defines `gold` as an optional source reading and prioritizes only an exact candidate already returned by analysis.
- `packages/biblia/src/levels.ts:70-96` recomputes the same candidate ordering for page marks and falls back to form IDs when no creditable lemma exists.
- `packages/golearn-extension/src/popup/card.ts:831-947,1055-1077` shows generated/sourced paradigm states and period variants separately; missing source data stays empty/unavailable rather than fabricated.

Potential conflation to guard against in future changes: `he` is the learner's language ID for Biblical Hebrew, Modern Hebrew, and (distinctly tagged) Biblical Aramaic; `el` covers Koine, Ancient and Modern Greek periods. Keep period/heritage IDs and source labels attached throughout lookup, card display, and repository events. Do not conflate the surface spelling, candidate lemma, and source's lemma/code pair. The current `gold` path requires a candidate `notes.lemmaId` plus `notes.code` match, so an index/alignment mismatch silently leaves the analyzer's own ordering intact rather than forcing the source annotation.
