# Audit: knowledge model (§17), spaced repetition (§18), GoListen (§19)

Date: 2026-10-09. Scope: `packages/repository-engine`, `repository-store` (memory and SQLite), `repository-linguistics`, `repository-contract`, GoReview's scheduler / intake / planner / exercise builders / facts provider, GoListen (`packages/golisten`), the packs' pronunciation blocks and the GoLearn extension's content-script pronouncer. No product code was changed. Every finding has a test.

## 1. Result in one paragraph

The model does what §17 asks on the cases that were constructed: four learners with four different "knows A, fails B" profiles each move exactly the (unit, dimension) pairs the evidence names and nothing else, on both stores, and a rebuild equals the live state. The scheduler is a thin, deterministic adapter over ts-fsrs and reproduces all 17 frozen reference numbers; the deck is a true fold, so concurrent devices, late arrivals, duplicates and a scheduler upgrade all behave as promised. GoListen's evidence-direction rule holds end to end on the real path: playback is exposure, synthetic and unreviewed audio never become listening evidence, and a reviewed test recording becomes eligible. **Nine defects** were found (D1 to D9, none critical, five medium), plus six observations. **Remediation (2026-10-09): eight are fixed and one is partly fixed (D7: the registries now exist and answer, but de and the three planned languages still cannot be heard).** Every `it.fails` was flipped to a plain `it` and is now the regression test of its fix; section 6.1 gives the files and the proving test per defect. No language has listening-evidence-grade audio today, and four of the seven product languages (hi, th, nb, nn) still have no voice, by design, until real ones are registered.

## 7. Observations (no failing test, worth knowing)

- **O1** `maximumInterval` is a soft cap. With a cap of 30 days Hard/Good/Easy gave 30/31/32 (Good path 0, 2, 11, 31, 31, 31). The scheduler README documents an overshoot for Easy only. Irrelevant at the default 36500 days (S10).
- **O2** `scoringMetadata` cross-checks eligibility against the provenance it recorded when it made the stimulus. `GoListen.assessment()` returns a *new* source each call; a second instance (or a session resumed after a reload) has no record and takes the descriptor's `eligibleForEvidence`/`synthetic` fields at their word. GoPractice keeps one instance (`createAudioDeps`), so the shipped path is covered (L9).
- **O3** The voice descriptor of a recording may name its file: the shipped demonstration clip's `voice.licence` contains `De-Guten_Tag.oga`, i.e. the phrase. It is part of `publicView(...).stimulus`. `assessment.ts` documents that the descriptor is shown only after the response.
- **O4** The extension's device-tag list for Spanish (`es`, `es-ES`, `es-MX`, `es-US`, `es-HN`) and the shared registry's (`es-HN`, `es-419`, `es-MX`, `es-ES`) differ: a bare `es` or `es-US` voice speaks in the reader but not in GoReview. The extension keeps its own copy of the tag table.
- **O5** A review dated before its `CardAdded` (a device clock behind) is not applied to the deck; it is reported in `ignored` (not silent) and still counts as evidence in the engine (S14). `Scheduler.review` itself throws the library's `FSRSValidationError` (not a `RangeError`) for a backwards date; `foldDeck` sorts by instant so it never triggers it (S9). De-duplication on `dedupeKey` lives only in the store (S16).
- **O6** The store never lowers a unit or relation status (`mayReplaceByRank`), so a unit row can only be superseded, never invalidated; invalidation lives on analyses. Eligibility must therefore always combine the unit with its live analyses; the engine and the exercise builders do, the facts provider's `status` does not (intake therefore also reads `facts.analyses`, D5).

## 8. What this audit did not cover

- No real audio, browser or device: speech, audio and the speech proxy are fakes; the live Azure service was never called. Voice availability on a real device was not measured.
- The FSRS maths themselves (it is a library; only the adapter, the identity stamp and the fold were audited) and the *calibration* of the model's numbers (the engine README calls them hypotheses; nothing here tests whether 0.8 vs 0.6 weights predict anything).
- GoReview's session runner end to end (its own tests cover it); `ReviewItemInvalidated` was built in the exact shape the runner emits and validated against the contract.
- `src/golisten` (the older app-side GoListen with its own Azure voice table) is a different implementation from `packages/golisten`; only the latter was audited.
